# MCP client and built-in web tools

- **MCP client, hand-rolled JSON-RPC**: the spec preferred `rmcp` (MIT/Apache) but it drags in ~336 transitive crates and its builder/transport API could not be pinned down without many build iterations in-session. The subset Xenon needs — `initialize` → `notifications/initialized` → `tools/list` → `tools/call` over stdio and Streamable HTTP, 60 s timeouts, output truncation — is small and hand-written in `src-tauri/src/mcp.rs`. Revisit `rmcp` if/when we need resources/prompts/sampling or the dependency count matters more than the code.
- **Lazy connect, turn-scoped**: MCP servers start on the first agent turn that needs them (`build_agent_async` in `runtime.rs`), not at app launch. `mcp_start_at_launch` exists but defaults off. Stdio children are killed when the turn's agent drops (`StdioConn::Drop`), which covers "shutdown on quit" without a global registry. Restart-on-crash uses a simple 2 s/4 s/8 s backoff then gives up for the turn; a later turn retries from scratch.
- **Built-in tools, not plugins**: `web_search`, `web_extract`, `web_research`, `wikipedia`, `fetch_json` live in `src-tauri/src/webtools.rs` as `Tool` impls, so they are always registered after the agent's default tools and cannot be dropped by `max_mcp_tools`. Search order is Brave → Tavily → Serper → SearXNG → DuckDuckGo HTML/lite; DuckDuckGo is the no-key default. html→markdown uses `htmd` (Apache-2.0); `r.jina.ai` is the fallback extractor. 8 s per request, 10 min in-memory cache, `web_tools_enabled` kills the whole section with one flag.
- **Import is read-only**: `mcp_import.rs` reads Claude Desktop, Claude Code, Cursor, Windsurf, VS Code, and OpenCode configs with six separate parsers (the shapes differ enough that one parser would be guesswork), keeping `source` on each server. Nothing is imported silently: the settings UI lists candidates with checkboxes, pre-checked only for servers whose command is on a tiny allowlist (`npx`/`uvx` with an `@modelcontextprotocol/`-style package, or a known-safe binary). Everything else needs an explicit click. Secrets found in those files are moved into the existing Keychain blob on import, never written to `config.json`.
- **Secrets stay in the Keychain**: `config.rs` `McpServer` has `env_secrets`/`header_secrets` (names only); values live in the existing `com.xenon.app` keychain item under `mcp:<server>:<NAME>` and `search:<kind>`. `without_secrets` (already used for `config.json`) is unchanged — the new fields carry no plaintext by construction.
- **`max_mcp_tools` default 40**: generous enough for a real install (Claude Desktop defaults to ~15–25 tools across servers) and low enough that a hostile or broken server cannot blow up the system prompt. It caps only MCP tools; built-ins and agent tools are unaffected.
- **Mock server instead of network in tests**: `src-tauri/src/mcp_mock.rs` is a real stdio MCP server (echo/add/sleep/crash) that runs inside the test executable — tests spawn `current_exe` with a guarded `mcp_mock_server_entry` test (`--exact … --nocapture` plus `XENON_MCP_MOCK_CHILD=1`) and speak JSON-RPC over stdio. No separate bin is built (a sibling bin leaked into `Xenon.app/Contents/MacOS/` and broke codesign), so plain `cargo test` works on a clean checkout and `cargo tauri build` bundles only `xenon`.
